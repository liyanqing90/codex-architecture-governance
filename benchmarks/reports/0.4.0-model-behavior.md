# Version 0.4.0 model behavior evidence

Observed on 2026-07-29 with `codex-cli 0.146.0-alpha.3.1`.

## Method

- Ten outcome-neutral, read-only fixtures.
- Two identified models.
- Three fresh, ephemeral Codex processes per model and case.
- Sixty accepted trials in total.
- Ground truth was not included in prompts, fixture names, or fixture content.
- Finding IDs were constrained to machine Rule Packs.
- Paths, line ranges, and excerpts were resolved against fixture bytes.
- The adapter permitted at most one evidence-only correction and failed a trial
  if the corrected evidence was still invalid.
- Solution decisions used canonical option IDs and atomic trade-off IDs.
- Run schema 1.4 bound source commit `ca63aa6e5d6785725232d5a344943d623f893ab4`,
  a clean relevant-input state, Darwin arm64 / CPython 3.13.0, dependency and
  configuration hashes, plugin manifest and Skill version, fixture tree
  manifests, exact runner/adapter bytes, reconstructible command templates,
  and command/model runtime executable plus version fingerprints.
- A canonical JSONL record preserved the exact argument vector and bound the
  command, stdout, stderr, observation, and outcome hashes for every accepted
  trial.

The complete structured trials, execution logs, and deterministic scores are
preserved in:

- `benchmarks/results/gpt-5.6-terra.yaml`
- `benchmarks/results/gpt-5.6-terra.log.jsonl`
- `benchmarks/results/gpt-5.6-terra-score.json`
- `benchmarks/results/gpt-5.6-sol.yaml`
- `benchmarks/results/gpt-5.6-sol.log.jsonl`
- `benchmarks/results/gpt-5.6-sol-score.json`

## Interpretation

Both models avoided every fixture-specific forbidden recommendation and never
selected an over-designed target. Evidence validity reached 1.0 after bounded
validation, every cited Knowledge ID existed in the catalog, and both complete
provenance chains passed source and execution-log verification. Rejected-option
explanations and reversible migration slices were complete in both runs.

The results do not establish universal architecture competence. Both models
still missed recovery and tool-authority rule families in the durable approval
case. Terra emitted a transaction false positive in two negative SQLite
trials; Sol emitted five false positives across the bounded corpus. Severity
still varied on shared data ownership and transactions. Terra sometimes chose
the wrong server-first mobile option; both models omitted some required
case-study knowledge. Required-knowledge coverage was 0.792 for Terra and
0.625 for Sol. Terra omitted some recovery, client-complexity, team-ownership,
and evaluation trade-offs; Sol reached complete recommendation accuracy and
decision stability in this run, not as a general guarantee.

These are retained as measured limitations rather than rewritten ground truth.
Scores are time-bound evidence for the named model requests, Codex executable
surface, fixtures, plugin version, source commit, and recorded execution
environment only. The remote model implementation and nondeterministic outputs
cannot be reconstructed from local executable provenance and are not claimed
as reproducible.
